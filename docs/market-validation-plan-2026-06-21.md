# DroneDoctor 7 天需求验证计划

**版本**：v1.3.0

**周期**：连续 7 天

**目标**：验证用户是否真的需要无人机故障辅助诊断，而不是只验证“愿不愿意加微信领免费券”。

## 用户路径

1. 用户通过内容、社群或熟人介绍添加微信。
2. 用户说明一个真实的无人机故障或维修学习问题。
3. 管理员生成一张兑换券，复制后自动标记为“已发放”。
4. 用户在网站激活兑换券，获得 3 天匿名体验通行证。
5. 用户至少完成一次诊断，并提交“有帮助 / 没帮助 / 看不懂”反馈。
6. 对有真实故障的用户，在微信中追问最终处理结果。

## 每天记录

管理员后台记录以下客观数据：

- 新增微信人数；
- 有真实问题的人数；
- 已发放兑换券数；
- 已激活兑换券数和激活率；
- 实际开始诊断人数；
- 完成诊断人数和完成率；
- 有帮助、没帮助、看不懂的反馈数；
- 用户是否愿意再次使用或推荐给同行。

微信沟通另外记录三句话：

1. 你当时最想解决的具体问题是什么？
2. 诊断结果中哪一步真正帮到了你，哪一步没有？
3. 下次再遇到类似问题，你会不会主动打开这个工具？为什么？

## 判断标准

以下标准用于决定下一步，不作为对外宣传承诺。

| 结果 | 建议判断 |
|---|---|
| 20 人以上添加微信，少于 30% 能说出真实问题 | 引流内容有效，但需求质量不足；先调整获客渠道和话术 |
| 已发券用户激活率低于 40% | 领取动机弱或激活流程仍有摩擦 |
| 激活后开始诊断率低于 60% | 用户没有迫切问题，或首页价值表达不清 |
| 开始诊断后的完成率低于 50% | 诊断流程太长、问题不匹配或回答质量不足 |
| “有帮助”反馈低于 50% | 暂缓扩量，优先修复诊断质量 |
| 至少 10 名真实用户完成诊断，且 60% 以上反馈有帮助 | 可以继续投入下一轮验证 |
| 至少 5 名用户主动再次使用、追问或转介绍 | 出现较强需求信号，可验证留存与专业场景 |

样本少于 10 名完成诊断用户时，只记录现象，不下“有市场”结论。

## 本轮优先级

### P0

- 每张实际发出的券都使用“复制并标记发放”，保证激活率分母真实。
- 每位用户必须带着真实问题体验，避免为了领券而产生虚假使用数据。
- 每次体验后追问故障结果，并要求提交站内反馈。

### P1

- 对“没帮助”和“看不懂”的案例做原因分类。
- 统计用户来源，比较内容、社群、熟人介绍的有效问题率。

## 本轮不做

- 不恢复普通账号、个人中心和云端历史记录；
- 不测试会员价格和支付意愿；
- 不批量免费发券制造虚假活跃；
- 不把加微信人数、访问量或领取券数量单独当作市场成立证据；
- 不根据少量好评宣称诊断准确率。

## 第 7 天复盘输出

复盘只回答四个问题：

1. 哪类用户带来的问题最真实、最迫切？
2. 哪类故障最容易被工具有效帮助？
3. 用户在哪一步流失，原因是什么？
4. 下一轮应继续、调整方向，还是停止投入？
