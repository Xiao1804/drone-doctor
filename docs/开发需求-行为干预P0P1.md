# 行为干预功能开发需求说明

> 直接发给开发同学，按优先级做就行。有问题随时沟通。

---

## 一、背景

产品目标指标：工具使用率>30%、付费转化率>2%、7日留存率>15%

通过行为心理学优化用户旅程，提升这些指标。本次改造不改变核心业务逻辑，只改**前端UI交互**和**埋点**。

---

## 二、P0：上线前必须完成（约3天）

### 任务1：诊断输入页改造（1天）

**现状**：用户在输入框里随便写，经常描述不清，AI诊断失败。

**改造要求**：

把自由输入改成**结构化三步选择**：

```
第1步：选机型（6个按钮，圆角卡片，带图标）
- Mavic系列
- Air系列
- Mini系列
- Phantom系列
- T30/T40（植保）
- 其他

第2步：选故障类型（6个按钮，圆角卡片，带图标）
- 无法起飞
- 图传异常（黑屏/卡顿）
- 云台故障（卡住/抖动）
- 电池问题（鼓包/充不进电）
- GPS信号异常
- 其他（点击后弹出文本输入框）

第3步：补充描述（选填，文本框）
- 占位符文字："例如：飞行时突然发生、已尝试重启"
```

- 最后一个按钮："开始诊断"
- 底部始终显示："今日剩余 X 次免费诊断"

**数据透传**：把选中的机型和故障类型一起发给后端API（作为 `deviceType` 和 `faultType` 字段，和原有 `symptom` 文本拼接）。

### 任务2：诊断等待页改造（0.5天）

**现状**：调AI接口时页面空白，用户容易刷新或离开。

**改造要求**：

```
┌─────────────────────────────────────────┐
│     🤖 AI正在分析你的故障...              │
│                                         │
│     [██████░░░░] 65%                     │
│                                         │
│     正在：匹配故障案例库...               │
│                                         │
│     ─────────────────────────            │
│     💡 小知识：                            │
│     70%的"无法起飞"故障原因是             │
│     电池电量不足或GPS信号弱。            │
│     ─────────────────────────            │
│                                         │
│     已完成 12,847 次故障诊断              │
│                                         │
└─────────────────────────────────────────┘
```

**进度条逻辑**（前端定时器控制，与真实后端进度无关）：
- 0→33%：2秒，文案"正在解析故障描述..."
- 34→66%：2秒，文案"正在匹配故障案例库..."
- 67→99%：2秒，文案"正在生成排查步骤..."
- AI结果返回后直接跳100%

**小知识**：准备15-20条文案（我会提供），页面打开后每3秒随机切换一条。

**已诊断次数**：后端提供一个 `/api/stats/total-diagnoses` 接口，返回 `{"total": 12847}`。前端定时器里直接显示这个数字。

### 任务3：诊断结果页改造（1天）

**现状**：AI返回后只显示文本，没有下一步引导。

**改造要求**：

结果页结构改成**三段式**：

**第1段：诊断摘要**（始终可见）
```
✅ 诊断完成！

故障类型：动力系统/传感器系统
最可能原因：下视视觉传感器被灰尘遮挡
预计解决时间：10分钟
难度：⭐⭐
```

**第2段：排查步骤**（默认只显示前2步，点"展开全部"才显示剩余）
```
步骤1：检查起飞面
- 操作：观察起飞面是否为平整、哑光的地面
- 判断标准：避免纯黑、镜面、强反光区域

步骤2：清洁下视传感器
- 操作：用超细纤维布擦拭无人机底部传感器

[展开全部 5 步 ▼]
```

**第3段：行动引导区**（结果页底部，三个卡片并排）

卡片1：
```
📋 还需要更多帮助？
查看维修知识库 →
```

卡片2：
```
🎯 这个故障解决了吗？
[解决了 ✓]  [还没解决]
```

卡片3：
```
💾 保存诊断结果
[微信扫码登录]
（[暂时不用]）
```

**反馈按钮交互**：
- 点击"解决了"：出现 ✅ 放大动画 + 弹出文字"太好了！"
- 点击"还没解决"：弹出两个选项 → "换个关键词再试" / "查看相关教程"
- 两个点击都要触发埋点

**社会认同**：结果页最底部，一行灰色小字
```
本月已有 234 人诊断了类似问题
```
这个数字从后端 `/api/stats/similar-diagnoses?deviceType=xxx&faultType=xxx` 接口获取。

### 任务4：全局次数指示器（0.5天）

**现状**：用户不知道用了几次，第4次突然提示付费，体验差。

**改造要求**：

页面右上角固定一个指示器，诊断全流程都显示：

```
状态1（剩余3次）：  ●●●○○  今日剩余 3 次   [蓝色]
状态2（剩余2次）：  ●●○○○  今日剩余 2 次   [蓝色]
状态3（剩余1次）：  ●○○○○  今日剩余 1 次   [橙色] ← 颜色变化！
状态4（用完了）：   ○○○○○  今日已用完       [灰色]
```

第3次使用时（剩余1次），在诊断输入页底部额外显示一个**非弹窗提示条**：

```
⚡ 这是你今天最后一次免费诊断
升级会员，无限次诊断 + 完整知识库
仅需 39元/月（每天1.3元）
[查看会员权益]
```

**重要**：这个提示条是内嵌在页面底部的，不是modal弹窗。用户可以忽略继续操作。

### 任务6：渐进式注册引导（上线后第2周）

## 四、埋点要求

所有改造都需要加上埋点，事件名和字段如下：

```javascript
// 1. 开始诊断
track('diagnosis_start', {
  source,       // 'hero' | 'header' | 'direct'
  device_type,  // 'mavic' | 'air' | 'mini' | 'phantom' | 't30' | 'other'
  fault_type,   // 'power' | 'video' | 'gimbal' | 'battery' | 'gps' | 'other'
  remaining_free // 3 | 2 | 1 | 0
});

// 2. 诊断完成
track('diagnosis_complete', {
  duration_ms,  // 从点击按钮到结果返回的毫秒数
  steps_count,  // AI返回的步骤数量
  difficulty    // 难度等级 '1'-'5'
});

// 3. 反馈按钮
track('feedback_given', {
  result,       // 'solved' | 'unsolved'
  diagnosis_id  // 诊断记录ID
});

// 4. 付费墙页面浏览
track('paywall_seen', {
  remaining_free // 0
});

// 5. 付费墙操作
track('paywall_action', {
  action        // 'upgrade' | 'come_back' | 'browse_free'
});

// 6. 注册引导展示
track('register_prompt_seen', {
  diagnosis_count // 当前第几次诊断触发的
});

// 7. 注册引导操作
track('register_prompt_action', {
  action        // 'register' | 'skip'
});
```

埋点上报到现有后端 `/api/events` 接口（如果已有）。没有的话新建一个，字段存JSON到 `events` 表即可。

## 五、接口需求

需要后端额外提供3个接口：

```javascript
// 1. 总诊断次数统计（用于等待页显示）
GET /api/stats/total-diagnoses
Response: { "total": 12847 }

// 2. 相似诊断次数（用于结果页社会认同）
GET /api/stats/similar-diagnoses?deviceType=mavic&faultType=power
Response: { "total": 234, "period": "本月" }

// 3. 事件上报（用于埋点）
POST /api/events
Body: { "event": "diagnosis_start", "data": {...}, "timestamp": "..." }
Response: { "ok": true }
```

## 六、设计稿参考

参考文档里的界面结构图（ASCII画的那个），视觉风格保持和现有页面一致。几个重点：

1. **诊断输入页**的机型/故障类型用卡片按钮，不是下拉菜单。带图标，圆角，hover高亮。
2. **等待页**的进度条要有动画感，不是瞬间跳。小知识文案用卡片样式，每3秒淡入淡出切换。
3. **结果页**排查步骤默认折叠，只显示前2步。展开按钮要明显。
4. **次数指示器**的圆点用小实心圆，蓝色→橙色→灰色过渡要平滑。
5. **所有注册/付费引导**都不能是弹窗modal，必须是页面内嵌的卡片。"跳过/暂时不用"按钮必须存在且可见。
