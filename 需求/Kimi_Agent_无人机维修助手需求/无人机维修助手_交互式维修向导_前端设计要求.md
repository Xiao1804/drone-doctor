# 无人机维修助手 — 交互式维修向导前端设计要求

## 产品定位

这是一个**工业级交互式维修向导工具**，核心使命是"站在维修工旁边，一步步告诉TA该做什么"。

它不是传统意义上的"网站"或"展示页"，而是一个**数字化的智能维修搭档**。维修工在机库、野外场地甚至夜间环境中，面对一架需要检修的无人机时，打开这个工具，它能：
- 告诉维修工**第一步做什么**
- 完成后引导**下一步看什么**
- 发现异常时立即提示**异常了怎么办**（分支到排故流程图）
- 每一步都关联对应的**维修手册章节**和**技术图纸**

**核心设计原则：在油污、昏暗、戴手套、时间紧迫的工业现场，信息必须一眼可见、操作必须一步到位。**

---

## 1. 使用场景与环境适配

### 1.1 典型使用环境
| 场景 | 光线条件 | 设备状态 | 操作限制 |
|------|---------|---------|---------|
| 室内机库 | 中等/强光 | 双手可用 | 可能有油污 |
| 野外场地 | 强光直射 | 一手持设备一手操作 | 戴手套 |
| 夜间紧急维修 | 极弱光线 | 借助手电筒 | 时间极紧迫 |
| 高空/狭窄空间 | 变化光线 | 单手持握 | 身体姿势受限 |

### 1.2 环境适配设计要求
- **高对比度模式优先**：所有关键信息和操作元素必须满足 WCAG 2.1 AA 级对比度标准，即使在强光直射或昏暗环境下也能清晰辨识。
- **深色模式为默认主题**：深色背景（`#0A0F1E`）在夜间和暗光环境下对眼睛更友好，同时让高亮的步骤指引更加醒目。
- **亮色模式可选切换**：提供浅色主题供光线充足的机库环境选择，切换入口必须在全局导航中常驻。
- **"脏手友好"设计**：所有可点击区域最小尺寸为 **56x56px**（超过 Apple HIG 的 44px 标准），按钮之间保留至少 **16px** 的安全间距，防止戴手套时的误触。
- **指纹/油污容错**：界面背景采用深色系，减少指纹和油污的视觉干扰；避免使用纯白色大面积区域作为主要内容背景。

## 2. 配色方案

### 2.1 主色调
| 色彩角色 | 色值 | 用途 |
|---------|------|------|
| 深空背景 | `#0A0F1E` | 全局深色模式背景，吸收环境杂光，让内容聚焦 |
| 卡片表面 | `#141B2D` | 步骤卡片、面板背景，与主背景形成微妙层次 |
| 深蓝灰 | `#1E2746` | 次级卡片、已完成的步骤、折叠面板 |
| 边框/分割线 | `#2A3555` | 卡片边框、步骤之间的连接线 |

### 2.2 功能色彩（高饱和度，确保远距离可见）
| 色彩角色 | 色值 | 用途 |
|---------|------|------|
| 行动主色 | `#00D4AA`（工业青） | 当前步骤高亮、主要操作按钮（"已完成，下一步"） |
| 警示色 | `#FFB800`（警示琥珀） | 警告状态、需谨慎操作的步骤（"注意：先断电"） |
| 故障色 | `#FF4757`（故障红） | 异常分支入口、故障状态、紧急停止 |
| 信息色 | `#3B82F6`（技术蓝） | 查看手册链接、技术图纸按钮、辅助信息 |
| 成功色 | `#10B981`（完成绿） | 步骤完成确认、检查通过状态 |

### 2.3 文字色彩
| 色彩角色 | 色值 | 用途 |
|---------|------|------|
| 主标题/步骤编号 | `#FFFFFF` | 当前步骤标题、关键指令 |
| 正文/操作说明 | `#CBD5E1` | 操作描述、注意事项 |
| 辅助文字 | `#64748B` | 备注信息、已完成步骤的描述（弱化） |
| 暗色背景上的强调 | `#00D4AA` | 关键术语、需特别注意的动作词汇 |

### 2.4 状态色编码（维修场景专用）
- **待执行**：灰色边框 + 灰色文字 `#64748B`
- **进行中（当前）**：工业青发光边框 `#00D4AA`，带有呼吸灯效果
- **已完成**：成功绿勾 `#10B981` + 文字淡化
- **异常/需排故**：故障红脉冲 `#FF4757`，吸引立即注意
- **阻塞/等待**：琥珀色 `#FFB800`，需先完成前置条件

## 3. 排版规范

### 3.1 字体选择
- **主字体**：`Inter` 或 `Roboto` — 无衬线字体，在各类工业平板上都有良好的渲染效果，数字和字母的区分度高（如 0 和 O，1 和 l）。
- **等宽字体**：`JetBrains Mono` — 用于无人机型号、故障代码、零件编号（如 `M300-RTK-V2.3.1`），确保字符对齐和准确识别。

### 3.2 字号层级（针对"一眼看清"优化）
| 层级 | 字号 | 字重 | 用途 |
|------|------|------|------|
| 巨型步骤编号 | 72px / 96px | 800 | 当前步骤的大号序号（如"STEP 03"），占据视觉中心 |
| 步骤标题 | 28px - 32px | 700 | 当前要做的事情的一句话概括 |
| 操作指令 | 20px - 24px | 600 | 具体的动作描述 |
| 正文 | 16px - 18px | 400 | 详细说明、注意事项、手册引用 |
| 辅助标签 | 14px | 500 | 零件名称、工具名称、状态标签 |

### 3.3 排版原则
- **一句话原则**：每个步骤的核心操作必须在 **一行（不超过 12 个字）** 内说清。
- **动作前置**：指令以动词开头——"拆卸螺旋桨"、"检查电池触点"、"测量电压值"。
- **数字突出**：所有数值（电压 24.5V、扭矩 2.3N·m）使用等宽字体 + 主色高亮。

## 4. 核心界面组件

### 4.1 步骤引导卡片（Step Card）—— 最核心的组件

这是维修工 80% 时间都在看的组件，设计必须极致清晰：

```
┌──────────────────────────────────────────────┐
│  ┌────┐  STEP 03 / 12                         │  ← 步骤进度指示
│  │ 03 │  拆卸螺旋桨组件                       │  ← 步骤标题（28px粗体）
│  └────┘                                       │
│──────────────────────────────────────────────│
│                                              │
│  [图示区域：螺旋桨锁定机构的高清示意图]          │  ← 可缩放的技术插图
│                                              │
│──────────────────────────────────────────────│
│  操作说明：                                   │
│  1. 按住桨毂中心锁定按钮（图中①所示）          │  ← 带编号的分步说明
│  2. 逆时针旋转桨叶 30° 至解锁位                │
│  3. 垂直向上拔出桨叶                          │
│                                              │
│  ⚠️ 注意：必须先断电！电池指示灯完全熄灭后      │  ← 警告框（ amber 底色）
│     等待 30 秒再进行此操作                    │
│                                              │
│──────────────────────────────────────────────│
│                                              │
│  [📋 查看维修手册]  [🔍 查看零件图]           │  ← 辅助信息入口（小按钮）
│                                              │
│  ┌──────────────────────────────────────┐    │
│  │     ✅ 已完成，进入下一步             │    │  ← 主操作按钮（56px高）
│  └──────────────────────────────────────┘    │
│                                              │
│  ┌──────────────────────────────────────┐    │
│  │     ⚠️ 发现异常，去排故               │    │  ← 异常分支入口（红色）
│  └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
```

**设计细节：**
- 步骤编号采用 **96px 的巨型数字**，配合工业青色 `#00D4AA`，占据左上角，让维修工在几米外扫一眼就知道做到第几步了。
- 卡片整体带有微妙的顶部发光边框 `box-shadow: 0 -2px 0 #00D4AA, 0 0 30px rgba(0, 212, 170, 0.15)`，模拟"当前激活"的状态感。
- 图片区域支持**双指缩放**和**平移**，点击可全屏查看。
- 警告信息必须带有图标 + 琥珀色左侧边框，与正常内容严格区分。
- 两个底部按钮的高度至少 **56px**，圆角 **12px**，文字 **18px 粗体**。
- **异常按钮**虽然颜色醒目，但视觉层级应略低于"完成"按钮（可通过尺寸或位置做区分），避免维修工习惯性误点。

### 4.2 排故流程图组件（Troubleshooting Flow）

当维修工点击"发现异常"后进入的决策树界面：

**布局方式：垂直决策树（移动端友好）**
```
问题：桨叶拆卸阻力过大
│
├─→ 选项 A：可以旋转但无法拔出
│   └─→ [诊断] 锁定机构卡滞
│       └─→ [解决方案] 使用 WD-40 喷涂锁定槽...
│
├─→ 选项 B：完全无法旋转
│   └─→ [诊断] 内部齿轮损坏
│       └─→ [解决方案] 更换桨毂组件（零件号：...）
│
└─→ 选项 C：旋转顺畅但拔出后有异响
    └─→ [诊断] 轴承磨损
        └─→ [解决方案] 更换桨叶轴承（零件号：...）
```

**设计细节：**
- 采用**垂直时间线/决策线**布局，而非传统的横向流程图，更适合手机和平板的纵向滚动习惯。
- 每个分支节点是一个可点击的卡片，点击后展开详细的诊断说明和解决方案。
- **当前激活的分支**用工业青色高亮，其他分支弱化（透明度 40%）。
- 节点之间的连线使用 SVG 绘制，带有流动动画效果（类似数据流向），暗示"跟随这条路径"。
- 每个最终解决方案卡片必须包含：**问题原因**、**解决方案步骤**、**所需零件/工具**、**预估时间**、**安全注意事项**。

### 4.3 维修手册阅读器（Manual Reader）

手册内容的呈现方式：

**双栏布局（平板/桌面）：**
```
┌──────────────────────────────────────────────────┐
│  ◀ 返回维修流程          机载电池系统 - 第3.2节    │
├────────────────────────┬─────────────────────────┤
│                        │                         │
│  文字内容区域           │  技术图纸/实物照片区域    │
│  （可滚动）              │  （可缩放、可全屏）      │
│                        │                         │
│  关键术语点击后          │  图中标注热点可点击       │
│  右侧显示对应图示        │  显示零件名称和编号       │
│                        │                         │
│  [🔍 搜索手册]          │  [⬆ 上传现场照片对比]    │
│                        │                         │
└────────────────────────┴─────────────────────────┘
```

**设计细节：**
- 文字与图纸**左右分栏**，避免频繁上下滚动切换。
- 文字中的**零件名称**、**工具名称**使用信息蓝色高亮，点击后在右侧图纸中**自动定位并高亮对应区域**。
- 图纸支持**热点标注**（Hotspot）：预先在图纸上标记关键位置，点击后弹出该位置对应的操作说明。
- 提供**"现场拍照对比"**按钮：允许维修工拍摄现场实况，与手册中的标准图示进行左右对比（透明度叠加对比）。
- 搜索功能常驻顶部，支持按零件号、故障代码、关键词搜索，搜索结果以高亮形式标注在正文中。

### 4.4 全局导航与进度指示

```
┌──────────────────────────────────────────────┐
│  ◀ 返回任务列表    M300 RTK 例行检查    🔦⚙️ │  ← 顶部固定导航栏
├──────────────────────────────────────────────┤
│  [━━━●━━━━━━━━━━━━━━━━]  3 / 12 完成        │  ← 进度条（可点击跳转）
│   01  02  03  04  05  06  07  08  09  10...  │  ← 步骤圆点导航
└──────────────────────────────────────────────┘
```

**设计细节：**
- 顶部导航栏**固定悬浮**，始终可见。高度 **64px**，深色半透明背景 `rgba(10, 15, 30, 0.95)` + 底部模糊效果 `backdrop-filter: blur(12px)`。
- 进度条使用**分段式**设计（而非连续填充），每一段代表一个步骤，已完成段为工业青色，当前段为脉冲发光的工业青色，未开始段为暗色。
- **步骤圆点导航**：允许维修工快速跳转到已完成的步骤回顾，或预览后续步骤。已完成的步骤显示绿勾，当前步骤放大发光，未开始的步骤灰显。
- 右上角常驻 **手电筒按钮**（调用设备闪光灯）和 **设置按钮**。

## 5. 交互动效

### 5.1 步骤切换动画
- **完成步骤 → 下一步**：当前卡片向下滑出并淡出，新卡片从上方滑入并淡入。动画时长 **300ms**，缓动 `ease-out`。
- 切换时步骤编号的数字使用**滚动计数器效果**（如 03 → 04 的数字像老虎机一样滚动）。

### 5.2 异常分支切换
- 点击"发现异常"按钮时，整个界面产生一次轻微的**红色闪烁警告**（屏幕边框 `#FF4757` 发光 200ms），随后当前步骤卡片向左滑出，排故决策树从右侧滑入。
- 排故树中的分支展开使用**手风琴动画**，带有弹性缓动 `cubic-bezier(0.34, 1.56, 0.64, 1)`。

### 5.3 微交互
- **按钮按下反馈**：所有按钮在按下时（`:active` 状态）产生 `scale(0.96)` 的缩小效果，给维修工明确的触觉式反馈。
- **完成庆祝**：一个步骤（或整个任务）完成时，步骤编号处触发一次轻微的**粒子爆发动画**（绿色小光点），增强成就感。
- **进度条流动**：当前步骤的进度段带有从左到右的流动光效，暗示"正在进行中"。

## 6. 异常场景与边界状态

| 场景 | 设计处理 |
|------|---------|
| 网络中断（野外无信号） | 显示离线缓存提示："当前处于离线模式，显示已缓存内容"。已完成下载的步骤和手册可正常查看。顶部出现琥珀色离线横幅。 |
| 电池电量低（< 20%） | 顶部导航栏右侧出现红色闪烁电池图标，提示"请连接充电器"。 |
| 设备温度过高 | 弹出半透明遮罩警告："设备温度过高，建议降温后继续使用"，防止高温导致设备损坏。 |
| 维修中断（中途离开） | 自动保存当前步骤到本地存储，返回时弹出恢复提示："是否继续上次的 M300 RTK 检查？（做到第 5 步）" |
| 维修工误操作（点了已完成但实际没做） | 提供**步骤回退机制**：在进度条上点击已完成的步骤可回溯，但弹出二次确认："确认回退到步骤 3？后续步骤记录将清除。" |

## 7. 响应式适配

### 7.1 平板（主要设备，10-12 寸）
- 默认横屏使用，步骤卡片居中，最大宽度 **800px**。
- 手册阅读器使用左右分栏。
- 排故流程图使用垂直决策树，节点卡片宽度 100%。

### 7.2 手机（备用设备，紧急情况下使用）
- 步骤卡片全宽，图片区域可点击全屏查看。
- 手册阅读器改为上下分栏（文字在上，图片在下），或 Tab 切换。
- 底部操作按钮固定悬浮在屏幕底部（iOS 需适配安全区），确保单手操作。

### 7.3 工业大屏（机库中的显示终端）
- 支持横屏展示整个排故流程图的全貌。
- 步骤卡片可放大到 **1200px** 宽度，文字和图片等比放大。
- 支持触控 + 鼠标操作。

## 9. 技术实现建议（供前端参考）

| 需求 | 推荐方案 |
|------|---------|
| 步骤状态管理 | React/Vue 状态机，每一步是一个状态节点 |
| 排故决策树 | 树形数据结构渲染，节点展开/收起用 Framer Motion / CSS Transition |
| 图片缩放查看 | 集成 `photoswipe` 或自研双指缩放手势 |
| 离线缓存 | Service Worker + IndexedDB，缓存步骤内容和手册图片 |
| 进度条分段 | SVG 绘制，支持点击跳转和流动动画 |
| 手电筒调用 | 浏览器 MediaDevices API（需 HTTPS 环境） |
| 图片热点标注 | 在图片上使用绝对定位的透明热区 `div`，坐标按百分比存储 |
| 深色/浅色切换 | CSS Variables 切换，避免两套样式表 |

## 10. 核心原则总结

1. **一步一屏**：每个步骤的核心内容必须在一个屏幕内完整呈现，无需滚动。
2. **一眼看懂**：从 2 米外扫一眼，维修工必须知道自己现在在做什么、做到哪一步了。
3. **一指操作**：所有关键操作必须在拇指可触及的范围内，戴手套也能准确点击。
4. **异常不迷路**：发现异常时，必须在 3 秒内进入排故流程，分支选择不超过 3 层。
5. **离线也能用**：关键内容必须本地缓存，网络断了维修不能停。

**这个产品的设计不是在"展示信息"，而是在"指挥行动"。每一个像素都应该让维修工的动作更快、更准确、更安全。**
